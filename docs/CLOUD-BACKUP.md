# GitHub 私有快照云备份

Dcode 的云备份用于找回**已经保存到磁盘、但可能尚未提交到 Git**的项目文件。它与 GitHub 上公开的 Dcode 源码仓库是两回事：每个备份目标都是连接账号自己拥有的**私有**仓库。Dcode 不会把项目备份到这个公开仓库，也不会把原项目的分支历史推送过去。

![Dcode 云备份设置](assets/cloud-backup-settings.png)

## 使用条件与开启步骤

目前仅支持 Windows 桌面端。需要安装 Git for Windows（包含 Git Credential Manager），并打开一个本地 Git 仓库的根目录。

1. 打开项目，进入「设置 → 云备份」，点击「浏览器登录」连接 GitHub。备份登录使用独立的 Git Credential Manager 命名空间和本机 DPAPI 凭证存储，不改动全局 `gh` 或 Git 配置。
2. 选择「新建私有仓库」，或选择同一 GitHub 账号下已有的 Dcode 私有备份仓库。已有目标必须可写、未归档，且带有 Dcode 备份标记；公开仓库会被拒绝。
3. 设置检查间隔与额外排除规则，点击「预览备份内容」。查看文件、已排除项和被阻止的文件；被阻止的文件需要先处理或排除。
4. 确认文件清单后点击「开启并首次备份」。此后只有应用运行且检测到文件变化时，才会创建新快照。需要时可点「立即备份」。

首次开启需要明确确认，切换仓库或导入已有云端仓库也不会自动授权上传。关闭自动备份会停止新快照，已经保留的快照不被删除；当前正在执行的一次操作完成后才生效。

## 快照包含什么

扫描基于项目当前磁盘文件和 Git 文件清单，覆盖已暂存、未暂存及未被 Git 忽略的新文件。已经删除的文件会在后续快照中消失。Dcode 把这些文件写入自己管理的独立 bare Git 仓库，使用项目/设备专用的 `snapshots/*` 分支上传；原仓库的 `HEAD`、索引、远端配置和提交历史不受影响。内容未变化时不会重复产生快照。云端确认后，界面才标记上传成功；失败可在后续检查时重试，手动备份不受自动重试退避限制。

默认排除 `.git`、Dcode 数据目录、依赖、缓存、构建产物、GitHub 工作流、环境文件和常见密钥文件。还可以按行添加 Gitignore 风格的排除规则，但不能通过反向规则重新加入受保护文件。扫描会阻止疑似凭证、LFS 指针、符号链接、子模块及特殊文件；限制为单文件小于 100 MiB、单快照至多 250 MiB、项目最多 20,000 个文件。

**边界：**未保存的编辑器缓冲区不会进入快照；原 Git 分支历史、LFS 对象、子模块内容和 Git 忽略的文件也不会进入。应用关闭后没有后台定时任务。凭证识别基于规则，不能保证发现所有秘密；上传前务必核对预览与 GitHub 仓库的私有状态。GitHub 上的私有仓库仍受 GitHub 账号权限和平台服务状态影响，不能替代离线备份。

## 找回代码

在「最近快照」中查看快照与差异，再选择「恢复副本」。Dcode 会把选定快照恢复到你指定父目录下的新文件夹，**不会覆盖当前项目**。也可以先读取已连接的私有备份仓库里的云端快照；读取本身不会开启上传。恢复后请检查文件、依赖和运行结果，再自行决定是否合并回原项目。

本功能的规则与实现边界记录在 [服务契约](../packages/services/src/cloud-backup/CONTRACT.md)；自动化测试入口为 `pnpm test:cloud-backup`。测试使用本地 Git 仓库和注入的 GitHub 边界，不能代替真实账号的上传验收。
